# 매드무비 프롬프트 한 장 — 클로드 코드에 그대로 붙여 넣기

맥에서 빈 폴더를 하나 만들고 클로드 코드(Opus 5.5)를 연 뒤, 아래 상자 안 전체를 붙여 넣는다.
003 강의에서 실제로 만든 댄스 매드무비(`scenes/dance.mad.js`)를 그대로 풀어 쓴 것이다.
빈 폴더에서 새 클로드 코드에게 이 프롬프트만 주고 돌려 봤다(2026-09-27). 설치 없이 약 40분 만에 15초 영상이 나왔다.

```text
너는 모션 디자이너이자 영상 편집자야. 아래 스펙대로 15초짜리 댄스 매드무비를 처음부터 끝까지 만들어 줘.
매드무비 = 음악 박자에 맞춰 영상을 자르고, 사람 누끼·큰 글자·효과를 얹은 짧은 영상.
영상 편집 앱은 쓰지 않는다. 전부 코드로 만든다: 장면은 HTML 한 장, 프레임은 헤드리스 크롬으로 한 장씩 찍고, ffmpeg로 영상을 만든다.

[0. 작업 환경]
- 이 폴더 안에서만 작업해. 맥(Apple Silicon) 기준이야.
- 필요한 것: Node 18 이상, ffmpeg, Google Chrome, swiftc(Xcode Command Line Tools). 없으면 설치 방법을 알려 줘.
- 헤드리스 크롬은 puppeteer-core로, 맥에 설치된 Chrome을 쓴다(크롬을 따로 내려받지 않는다).
- 애매한 건 멈추지 말고 합리적인 기본값으로 진행하고, 마지막에 무엇을 골랐는지 알려 줘.

[1. 소스 영상 — Mixkit 무료 스톡]
- 라이선스: Mixkit Stock Video Free License. 유튜브·상업 이용 가능, 출처 표기 의무 없음.
- 아이돌·방송·남의 유튜브 영상은 쓰지 않는다(권리가 없어서 올리면 저작권 신고 대상).
- 아래 4개를 쓴다. 주소 규칙: https://assets.mixkit.co/videos/<번호>/<번호>-1080.mp4 (1080이 없으면 -720)
  · 33899 연기 속 역광 실루엣 댄서 → 인트로·컷 배경 (이름: smoke)
  · 40367 체크 셔츠 댄서 → 주인공, 누끼 (plaid)
  · 51314 농구 코트 댄서, 뒤 벽화에 사람 그림 → 잔상, 누끼 (court)
  · 43210 폐건물 홀 댄서 → 컷·레터박스 배경 (hall)
- 전체를 받지 말고 ffmpeg로 앞부분만 가져온다: 8초(plaid는 12초).
- 30fps, 1920×1080 JPG 프레임으로 뽑는다 → clips/<이름>/00000.jpg … (ffmpeg는 기본이 00001부터라 -start_number 0)

[2. 누끼 — macOS 내장 Vision, 모델 다운로드 없음]
- Swift 커맨드라인 도구(cutout)를 만든다. 프레임 폴더를 받아, 사람만 남기고 나머지는 투명한 PNG 폴더(clips/<이름>-cut/)를 만든다. 크기는 원본과 같게.
  · 기본(사람 모드): VNGeneratePersonSegmentationRequest, qualityLevel = .accurate. 머리카락까지 잡는다.
  · --mode subject: VNGenerateForegroundInstanceMaskRequest(macOS 14+, 사진 앱 '피사체 들어올리기'와 같은 방식). 역광 실루엣처럼 사람 모드가 비어 버릴 때 쓴다.
  · --roi x,y,w,h (0~1 비율): 이 영역 밖 마스크는 지운다. 벽화·포스터 속 사람이 같이 잡힐 때 쓴다.
  · --feather: 가장자리를 1~2px 부드럽게.
  · 마스크는 원본 해상도로 키워서 원본 픽셀의 알파로 입힌다.
- 누끼는 plaid와 court만 딴다. court는 벽화 속 사람이 잡히니 --roi 0.27,0,0.73,1 을 준다. 골대 옆 작은 인물(가로 0.38~0.46)도 잡히니, 누끼를 단색 배경에 얹어 보고 남으면 가장 큰 덩어리만 남긴다.
- 다 딴 뒤 장마다 알파 평균을 재서 빈 장(사람이 안 잡힌 장)이 없는지 확인한다. 빈 장은 그 장만 --mode subject로 다시 딴다.

[3. 박자 — 모든 컷과 효과는 박 위에]
- 128 BPM. 1박 = 0.46875초(30fps에서 14.0625프레임). 1마디 = 4박. 8마디 = 32박 = 15초 = 450프레임.
- 프레임 f가 몇 번째 박인지는 매번 floor(f / 30 / 0.46875)로 계산한다. 시간을 더해 가며 세면 뒤로 갈수록 박이 밀린다.
- 구조: 1마디 인트로 → 2마디 라이저 → 3~7마디 드롭(5마디) → 8마디 엔딩. 드롭은 9번째 박(3.75초)에서 터진다.

[4. 음악 — 코드로 직접 합성, 저작권 걱정 없음]
- Node로 48kHz 16bit 모노 WAV를 만든다. 15초, 128 BPM.
  · 1마디(인트로): 박마다 낮은 '붐'(음높이가 뚝 떨어지는 사인파).
  · 2마디(라이저): 노이즈와 올라가는 음이 점점 커지고 붐은 점점 작아진다. 마지막 0.2초는 완전히 무음(드롭 직전에 숨을 멈추는 느낌).
  · 3~7마디(드롭): 박마다 킥, 2·4박에 클랩(짧은 노이즈), 박과 박 사이(뒷박)에 하이햇, 반 박마다 튀는 근음 베이스, 박마다 짧은 코드 스탭. 코드는 마디마다 C → Am → F → Dm 순서로 돈다.
  · 8마디(엔딩): 첫 박에 붐 한 번, C 코드 패드가 1.5초에 걸쳐 잦아든다.
- 난수는 시드를 고정한다(같은 코드 = 같은 소리).

[5. 디자인 — 1920×1080, 30fps]
- 색: 배경 #07030c, 글자 흰색, 강조 4색 #ff2d6f(핑크) #16e0bd(민트) #ffd400(노랑) #7c4dff(보라). 강조색은 박마다 돌아가며 쓴다.
- 폰트(Google Fonts):
  · 제목: Anton. 영문 6자 이하. 이번 제목은 "MOVE".
  · 자막: Black Han Sans, 120px, 화면 아래 가운데. 한글 8자 이하, 한 자막은 2박 동안. 글자마다 0.04초 간격으로 아래에서 튀어 오르며 등장(0.6배→1배), 검은 테두리 3px + 그림자.
- 레이어 순서(아래→위): 배경 영상·색 → 색 보정 → 흐르는 글자·뒤 글자 → 잔상 → 누끼 → 앞 글자 → 자막 → 흰 플래시.
- 규칙:
  · 한 화면에 효과(잔상·RGB 분리·글리치·흐르는 글자 같은 화면 효과)는 두 개까지만 겹친다. 줌·흔들림·펀치 같은 카메라 움직임은 세지 않는다.
  · RGB 분리(빨강·초록·파랑 채널을 좌우로 벌림)는 라이저와 박수 박에만 쓴다.
  · 강한 흰 플래시는 마디 첫 박에만 쓴다. 치는 순간 밝았다가 빠르게 사라진다.
  · 박 펀치: 박이 칠 때마다 화면이 1.07배로 커졌다가 곧 돌아온다.
  · 글자가 얼굴을 가리지 않게 한다.
  · 마지막 0.5초는 검은 화면으로 페이드아웃.

[6. 마디별 장면] (괄호 안 초는 그 소스 영상의 어느 지점부터 쓰는지)
1마디 · 인트로 (0~1.875초) — 글자가 하나씩
  - 배경 smoke(0.3초~). 박마다 밝게 번쩍했다가 어두워지고, 박마다 배경이 1초씩 건너뛴다(컷 느낌).
  - 가운데 "MOVE"(330px)가 박마다 한 글자씩 늘어난다: M → MO → MOV → MOVE. 새 글자는 1.35배에서 1배로 튀며 들어온다.
  - 박마다 화면이 잠깐 흔들리고, 약한 플래시.
2마디 · 라이저 (1.875~3.75초) — 긴장 쌓기
  - 배경 plaid(0.7초~). 큰 "MOVE"를 사람 뒤에 깐다(누끼가 글자 위). 글자는 점점 커진다(420→580px).
  - 줌(1→1.28배), 흔들림, RGB 분리(최대 40px), 채도가 점점 세진다. 제곱 곡선으로 끝에 몰리게.
  - 마지막 0.2초는 완전히 검은 화면. 음악도 무음.
3마디 · 드롭 ① 팝 (3.75~5.625초)
  - 단색 배경이 박마다 강조색으로 바뀐다.
  - 뒤에 "MOVE MOVE MOVE…" 외곽선 글자(260px) 4줄이 줄마다 반대 방향으로 흐른다(초당 420px).
  - plaid(2초~) 누끼에 두꺼운 흰 테두리(스티커처럼 6px) + 아래 그림자.
  - 드롭 첫 박에 강한 흰 플래시.
4마디 · 드롭 ② 잔상 (5.625~7.5초)
  - 배경 court(1초~) 원본, 채도 조금 올림.
  - 6·12·18프레임 전 누끼를 각각 초록·파랑·보라로 물들여 반투명하게 겹치고(스크린 합성, 불투명도 0.55·0.42·0.3), 지금 누끼를 맨 위에 올린다.
  - 자막: "멈추지 마"(1~2박) → "끝까지"(3~4박).
5마디 · 드롭 ③ 컷 (7.5~9.375초)
  - 박마다 hall(2초~) ↔ smoke(4초~)로 하드컷. 컷마다 짧고 약한 플래시.
  - 2·4박(박수)에 글리치: 화면을 가로 띠 4개로 나눠 좌우로 어긋나게(최대 60px) 하고 RGB 분리. 박이 지나면서 빠르게 잦아든다.
6마디 · 드롭 ④ 뒤 글자 (9.375~11.25초)

7마디 · 드롭 ⑤ 레터박스 (11.25~13.125초)

  - 가운데 "M O V E"(150px)의 자간이 마디 동안 40px에서 70px로 벌어진다.

  - 오른쪽 아래 작은 크레딧: "footage: Mixkit · edited by Claude".
  - 첫 박에 플래시, 마지막 0.5초 페이드아웃.

[7. 만드는 방식]
- 장면은 HTML 한 장. window.renderFrame(f)가 프레임 번호 f를 받아 그 순간의 화면을 그린다.
  · 같은 f에는 언제나 같은 그림. Math.random·Date는 쓰지 않고, 시드 난수만 쓴다.
  · 이미지가 다 로드(decode)된 뒤, 폰트는 document.fonts.load로 기다린 뒤 찍는다. 한글 폰트는 실제 자막 글자를 같이 넘겨야 그 글자가 로드된다(예: document.fonts.load('120px "Black Han Sans"', '멈추지 마 끝까지 지금 이 순간')).
- HTML은 로컬 서버로 띄운다(file://은 이미지 로드가 막힌다).
- puppeteer-core로 1920×1080 창을 열고 f = 0~449를 한 장씩 PNG로 찍는다. 나눠서 병렬로 찍을 땐 탭 여러 개 말고 브라우저를 따로 띄운다(안 보이는 탭은 멈춘다).
- ffmpeg: 프레임(30fps) + music.wav → H.264(yuv420p, crf 18) + AAC → out/mad.mp4

[8. 렌더 전에 스토리보드부터]

- 볼 것: 누끼 가장자리(머리카락), 글자가 얼굴을 가리는지, 글자가 화면 밖으로 나가는지, 빈 화면이 있는지.

[9. 렌더 후 검수]
- ffprobe로 1920×1080 · 30fps · 15초 · 오디오 스트림이 있는지 확인한다.
- 마디 경계 프레임(박 번호 × 14.0625를 올림: 0, 57, 113, 169, 225, 282, 338, 394)을 콘택트 시트로 뽑아 직접 본다. 드롭 안에 검은 프레임이 없는지, 컷과 플래시가 박에 맞는지.
```

## 바꿔 쓰기
- **제목:** "MOVE" 자리에 다른 영문 6자 이하를 넣는다.
- **자막:** 4마디·6마디 자막만 바꾼다(한글 8자 이하).
- **영상:** mixkit.co에서 dance를 검색하고, 영상 주소 끝 번호로 바꾼다. 전신이 보이고 사람과 배경 색이 다른 영상이 누끼가 잘 된다.
- **색:** 강조 4색만 바꿔도 분위기가 달라진다.
- **음악:** 가진 곡을 쓰려면 곡의 BPM과 드롭 위치에 맞춘다. 곡 라이선스는 따로 확인한다.
