## 2. 지금 바로 바꿀 것 3가지 (우선순위 순)
순서의 이유: ①은 10분이면 끝나고, ③으로 새로 올릴 쇼츠의 조회를 강의로 넘기는 통로다. ②는 그 통로 끝의 문이다(쇼츠의 관련 동영상 칸에 롱폼 제목이 뜸, 일반론). ③은 통로에 흘려보낼 물량이다.

### ① 쇼츠 → 롱폼 다리 놓기 [늘리기] — 무료, 10분
- **무엇을**: 쇼츠 18편 전부의 '관련 동영상'을 같은 강의 롱폼으로 지정(006-1~3 → 006 롱폼 …).
  롱폼 5편 '최종 화면' = 다음에 볼 강의 1편(지금은 가장 많이 본 004, 시청 지속 데이터가 생기면 다시 고름) + 재생목록 '클로드 코드로 만들기'.
- **어떻게**: Studio → 콘텐츠 → Shorts → 세부정보 → 관련 동영상. 앞으로 올리는 쇼츠는 업로드 화면에서 바로 지정.
  쇼츠 설명란·댓글의 링크는 눌리지 않으므로(일반론) 쇼츠 안에서 누를 수 있는 연결은 이 칸뿐.
- **기대 효과**: 같은 채널에서 '롱폼÷쇼츠'가 1.5%(006)~21.1%(004)로 벌어져 있다 → 다리에 따라 오를 여지. 다만 기존 쇼츠는 1,200 근처에서 멈춰 새 조회가 적어, 효과는 ③으로 새로 올릴 쇼츠에서 커짐(추측).
- **7일 뒤 숫자**: ⓐ 롱폼별 트래픽 소스에 'Shorts' 유입이 생겼나(0이면 설정 재확인).
  ⓑ JSON 재수집 때 강의별 '롱폼÷쇼츠'(001 2.6%, 006 1.5%)가 2배가 됐나(우리 목표치).

### ② 001·006 롱폼 제목+썸네일 한 묶음 교체 [시험] — 무료, 1~2시간
- **무엇을**: 3번의 추천 제목과 새 썸네일을 같은 날 함께 교체.
  설명란 첫 줄 = 약속 한 문장, 2~3줄째에 핵심어('클로드 코드 영상 만들기' / '멀티플레이 FPS 만들기'), 챕터 이름도 핵심어로.
- **어떻게**: 교체 전 Studio에서 두 영상의 '지난 7일' 노출수·노출 클릭률·조회수·30초 유지율을 적어 둔다. 썸네일은 지금처럼 코드(HTML)로 렌더.
  004에서 가져올 규칙: 주인공은 숫자나 장면 하나 / 큰 글자 3~4어절, 제목과 다른 말 / 오른쪽 아래·아래 15% 비움 / 강아지는 왼쪽·가운데, 시선은 주인공 쪽.
  테스트 및 비교(Test & Compare)는 무료지만 주간 노출 1,000 미만이면 결론이 안 남(일반론) → 노출이 적으면 추천안으로 한 번 교체 후 전후 비교. 노출이 충분하면 썸네일 고정, 제목 3개만 돌림(한 번에 한 변수).
- **기대 효과**: 같은 노출에서 더 많이 누름. 단, 001·006이 '클릭'에서 막혔을 때만. 30초 유지율이 낮다면 내용 문제라 포장 효과는 작음(지금은 구분 불가).
- **7일 뒤 숫자**: 교체 전 7일 vs 후 7일의 노출 클릭률·조회수. 통과선(우리 목표치) = 조회수 2배 + 노출 클릭률 상승. 참고로 이 채널 롱폼 최고치는 004의 일평균 14.6회.

### ③ 쇼츠 공백 없애기 + '강의당 서로 다른 각도 3개' [늘리기·끊기] — 무료, 매일
- **무엇을**: 강의와 강의 사이에도 쇼츠를 하루 1편 예약(시각은 상관없어 보이니 19:00 유지해도 됨). 소재는 이미 만든 롱폼에서 아직 안 쓴 장면.
  각도는 결과 장면 / 숫자·비용 / 막힌 점·실험 — 002·006에서 6/6 통한 구성.
  끊을 것: 같은 틀에 결과물만 바꿔 연달아 올리기(003-3~7, 5편 모두 하위).
- **어떻게**: 25~37초(우리 상위 쇼츠의 범위). 첫 프레임에 숫자·대비가 들어간 화면 문구(소리 꺼도 읽히게). 마지막 장면이 첫 장면으로 이어지는 루프. 업로드 때 ①의 관련 동영상 지정.
- **기대 효과**: 지금 비율(18편 중 8편, 44%가 상위)이면 7편 중 3편 안팎이 1,100회 이상(추정). 강의 공백 중에도 채널이 계속 시험대에 오름.
- **7일 뒤 숫자**: 새 쇼츠 각각의 공개 3일째 조회수. 7편 중 4편 이상이 1,000회 넘으면 통과(44% 초과). 1,300을 넘는 편이 하나라도 나오면 천장 돌파 신호.

### 롱폼 001 (49회) — 지금: 「클로드 코드로 영상 만들기 — 퀄리티 어디까지 될까? (Opus 5.5)」
- 약속 한 문장: 클로드 코드로 앱 홍보 영상까지 8종의 영상을 코드로 만드는 과정을 보여 준다.
- 새 제목:
  1. **클로드 코드로 영상 8종 만들기 — 앱 홍보 영상까지 (Opus 5.5)** ← 추천 (구체성: 결과 수치를 앞에)
  2. 클로드 코드로 앱 홍보 영상 만들기 (Opus 5.5 직접 해 봄) (검색형 '[도구]로 [결과] 만들기')
  3. 클로드 코드 영상 퀄리티, 앱 광고로 써도 될까? 직접 만든 8종 (질문 + 증거)
- 썸네일 큰 글자: **「이거 전부 코드」** (3어절)
  화면: 폰 1대에 가장 밝은 광고 장면(예: 알람 앱 '모닝콜 누가 깨워줄까?')이 주인공, 뒤에 코드 화면을 흐리게. 강아지는 왼쪽에서 폰을 봄. 나머지 폰 2대와 부제는 뺌.
- 이유: 001에서 유일하게 1,000회를 넘은 쇼츠(001-1, 1,226회)의 문장을 썸네일로. 제목은 '무엇을(8종)', 썸네일은 '놀라움(전부 코드)' — 지금처럼 같은 문장을 두 번 쓰지 않음.
- Truth: 롱폼에 8종이 다 나오는지 확인. 아니면 숫자를 실제 개수로.

### 롱폼 006 (55회, 쇼츠 3편 합 3,643회) — 지금: 「클로드 코드로 하루 만에 멀티플레이 FPS 게임 만들기 — 게임 서버비 0원 (WebRTC P2P)」
- 약속 한 문장: 클로드 코드로 하루 만에, 서버비 0원(WebRTC P2P)으로 실제 판교역 맵에서 여럿이 싸우는 브라우저 FPS를 만든다.
- 새 제목:
  1. **클로드 코드로 서버비 0원 멀티플레이 FPS 만들기 (하루 만에)** ← 추천 (핵심 이득을 9번째 글자로 당김 — 지금은 37번째)
  2. 브라우저 멀티플레이 FPS 게임 만들기 — 클로드 코드 + WebRTC P2P (검색형)
  3. AI로 멀티플레이 게임 만들면 꼭 막히는 4가지 (클로드 코드 FPS) (실수형, 006-3 1,219회 각도)
- 썸네일 큰 글자: **「진짜 판교역에서 총싸움」** (3어절)
  화면: 판교역이 알아보이는 게임 장면(표지판·출구가 있으면) + 총구 화염을 어둡게 덮지 말고 주인공으로. 글자 박스는 하나만, 칩 3개 삭제, 강아지는 왼쪽 가운데로.
- 이유: 쇼츠에서 이미 1,231회 통한 구체적 장면(판교역)을 썸네일이 보여 주고, 제목은 '어떻게(클로드 코드·서버비 0원)'를 말함 — 지금은 제목 문구를 썸네일에 반복해서 보여 주는 게 없음.
- Truth: 3안은 롱폼이 4가지를 다 다룰 때만.

### 쇼츠 004-2 (39회) — 지금: 「싼 AI도 선을 지킬까? (DeepSeek 수위 테스트)」
- 재료: 같은 강의에서 통한 숫자 대비(1,000번 21,000원 vs 231원 → 004-1 1,112회) + 선 넘는 요청 실험 + 결과는 감춤.
- 훅 후보 채점(Gap·구체성·Truth·Fit·말투·Pull 각 0~2, Truth·Pull은 통과/탈락 관문):

| 후보 (방식) | 점수 | 판정 |
|---|---|---|
| 231원 AI, 선 넘을까? (숫자+호기심) | 12 | 첫 1초 채택 |
| 90배 싼 AI 캐릭터 채팅, 선 넘는 요청 넣어 봤다 (실험) | 11 | 제목 1 |
| 231원짜리 AI 캐릭터, 어디까지 대답할까? (질문) | 11 | 제목 2 |
| 싼 AI도 선을 지킬까? (지금 제목) | 8 | 숫자 없음, Pull 약함 |
| 싼 AI 썼다가 앱 망할 뻔 (위험 과장) | — | Truth 0 → 탈락 |
| 싼 AI가 더 깐깐했다 (반전 단정) | — | 결과 확인 전 보류 |

- 새 제목:
  1. **90배 싼 AI 캐릭터 채팅, 선 넘는 요청 넣어 봤다 (DeepSeek)** ← 추천
  2. 231원짜리 AI 캐릭터, 어디까지 대답할까? (DeepSeek 테스트)
  3. AI 캐릭터 챗봇 만들기 전 꼭 해 볼 안전 테스트 (DeepSeek)
- 첫 1초 화면 문구: **「231원 AI, 선 넘을까?」** — 첫 화면: 채팅창에 요청을 치는 중(민감한 단어는 가림) + '1,000번 = 231원' 가격표.
- 첫 문장 대사: **"천 번 대화에 231원 드는 AI한테, 선 넘는 요청을 넣어 봤습니다."**
- 이유: 통한 쇼츠 8편엔 숫자나 대비가 있는데 지금 제목은 숫자 없는 질문. '수위'라는 단어는 빼서 제한 가능성을 낮춤(추측). 결과는 끝에서 공개하는 열린 고리로 남김.

### 쇼츠 003-7 (52회) — 지금: 「AI가 만든 15초 사진 일기 앱 광고」
- 재료: 완성도 있는 광고가 사실은 코드라는 반전 + 1인 개발자의 필요 + 채널에서 검증된 '이거 전부 코드' 프레임(001-1 1,226회).
- 훅 후보 채점:

| 후보 (방식) | 점수 | 판정 |
|---|---|---|
| 이 광고, 전부 코드예요 (반전) | 11 | 첫 1초 채택 |
| 이 앱 광고, 사람이 만든 것 같나요? (질문 → 댓글) | 11 | 제목 3 |
| 앱은 있는데 광고 영상이 없다면 (호명) | 9 | 제목 2에 녹임 |
| 앱 화면 → 15초 광고 (변신) | — | 앱 화면이 소재인지 확인 전 보류 |
| AI가 만든 15초 사진 일기 앱 광고 (지금, 설명형) | 7 | Pull 0 → 탈락 |

- 새 제목:
  1. **사진 일기 앱 광고, 이거 전부 코드예요 (클로드 코드)** ← 추천
  2. 1인 개발 앱 광고 영상, 클로드 코드로 만들기
  3. 이 앱 광고, 사람이 만든 것 같나요? (클로드 코드 15초 광고)
- 첫 1초 화면 문구: **「이 광고, 전부 코드예요」** — 첫 화면: 로고 말고 광고에서 가장 화려한 장면을 꽉 차게, 0:01에 코드 화면을 반쯤 갈라 보여 줌.
- 첫 문장 대사: **"이 15초짜리 앱 광고, 클로드 코드가 짠 코드로 만든 거예요."** (제작 방식이 다르면 그 부분만 사실대로)
- 이유: 같은 틀의 4번째(같은 틀 4편이 52~195회)라 새로움이 0이었다 → 각도를 '광고 소개'에서 '코드라는 반전'으로 바꿈.
  대안: 러닝·소개팅·알람·사진 일기 광고 4편을 한 편으로 묶어 '어느 게 제일 나아요?'로 다시 내기.

> 공통: 제목은 Studio에서 즉시 바뀌지만, 첫 1초·첫 대사는 영상을 다시 렌더해 새로 올려야 바뀐다. 새 편은 각도가 바뀐 새 컷이어야 반복 콘텐츠로 안 묶임.

## 4. 우리가 놓치고 있던 것: 쇼츠 '조회수'를 '본 사람 수'로 읽어 왔다
- **데이터**: 상위 쇼츠 8편이 1,112~1,262의 좁은 구간에 몰리고 며칠 안에 멈춘다(1,300 넘은 편 0). 그 8편도 좋아요 1~7개(0.09~0.57%). 쇼츠 11,912회에 구독 9명.
- **일반론(스킬 참고 자료, Studio에서 확인 필요)**: 2025-03-31부터 쇼츠는 재생이 시작되기만 해도 1회로 센다.
  실제로 본 수는 '참여한 조회수(Engaged views)', 넘겼는지는 '조회됨 vs 스와이프로 넘김(Viewed vs Swiped away)'에 따로 있다. 보통 '좋음' 기준은 조회됨 75%+, 평균 조회율 70%+.
- **추측**: 1,200은 '첫 시험 노출에서 대부분이 넘긴 뒤 멈춘 값'일 수 있다. 그렇다면 "쇼츠는 되는데 롱폼이 안 된다"는 전제부터 틀렸다 — 쇼츠도 아직 시험을 통과한 편이 없다.
- **할 일(무료, 10분)**: 18편의 조회됨 %·평균 조회율·참여한 조회수를 이 JSON에 칸으로 추가하고 매주 같은 표로 쌓는다. 쇼츠 순위를 조회수가 아니라 '조회됨 %'로 다시 매긴다 — 450회짜리 001-3이 1,200회짜리보다 덜 넘겨졌다면 따라 할 쇼츠가 바뀐다.
- **읽는 법**: 조회됨 %가 낮다 → 첫 1초 문제(③의 첫 프레임 규칙이 1순위) / 조회됨 %는 높은데 1,200에서 멈춤 → 중간 속도·루프 문제 / 둘 다 괜찮다 → ① 다리 문제.
- **가장 큰 이유**: 채널 조회의 96%가 이 숫자 하나에 걸려 있고, ①~③이 맞는 방향인지도 이 숫자를 봐야 안다.

## 적용한 스킬 기준
- analytics-and-reporting(METER): 목표→주 KPI 1+보조 2·7일 창 / 데이터에 있는 숫자만, 빈칸 표시 / 조회수 대신 신호 지표 / 자기 채널 내 상대 비교 + 표본·인과 주의 / 결과 먼저, 추천은 정확히 3개(늘리기·시험·끊기).
- youtube-long-form(CHAIN)·youtube-shorts(Retention Ladder): 포장 먼저(C), 진단 숫자 3개(I), 최종 화면·재생목록·쇼츠 다리(N / Bridge) / 첫 1초 무음 문구(Stop), 루프(Hold), 같은 틀 반복 금지(Angle).
- youtube-publishing-and-metadata(INDEX I·N): 핵심어와 결과 수치를 제목 앞쪽에, 명료함 우선, 설명 첫 줄 = 약속, 핵심어 이름의 챕터.
- thumbnail-design(CLICK): 약속 한 문장, 제목·썸네일 반복 금지(보여 주기 vs 말하기), 초점 하나, 0~4어절, 168×94 가독성, 오른쪽 아래·아래 15% 비움, 테스트 및 비교의 트래픽 조건.
- hook-writer: 내용에서 가장 강한 재료 추출 → 서로 다른 방식으로 5~6개 생성 → 6항목 채점(Truth·Pull 관문) → 화면 문구·첫 대사·첫 화면 3채널로 전달.
