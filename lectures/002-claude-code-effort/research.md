# 조사 — Claude Code effort 설정

원문: [Using Claude Code: Spending your effort](https://claude.dev/blog/spending-your-effort/) (Thariq Shihipar, claude.dev 블로그, 2026-09-25)
모델: Opus 5.5, Fable 5.1. 명령: Claude Code에서 `/effort` (대화 중간에도 바꿀 수 있고, 바꿔도 프롬프트 캐시가 깨지지 않음)

## 핵심 요약 (원문 기준)

- **effort란**: 이 작업에 컴퓨팅을 얼마나 쓸지 모델에게 알려 주는 대략적인 신호. 높을수록 스스로 판단하고 검증·엣지케이스 테스트를 더 많이 한다.
  - 원문 비유: 12시간 주면 끝까지 파고들고, 1시간 주면 요구를 충족하는 최선본을 내고 이어서 고치길 기대한다.
- **effort 곡선**: Opus 5.5와 Fable 5.1은 단계를 올릴 때마다 점수와 토큰이 함께 오른다 (Terminal-Bench 3.0, 70개 과제).

### 직접 만든 실험 3개 (Opus 5.5)

- **대충 시킨 작업** ("개인 운동 기록 앱 만들어줘")
  - 걸린 시간: low 1.5분, medium 4분, high 11분, max 67분
  - low는 기록과 간단한 그래프, max는 히트맵까지 만든다.
  - effort가 높을수록 Claude가 대신 정하는 게 많아진다.
- **어느 정도 정해 준 디자인 작업** (`/config` 메뉴 재설계)
  - low(1분)는 아이디어만 전하는 스케치, max(28분)는 실제 Claude Code 같은 목업에 흐름별 설명까지.
  - 저자는 이 경우 low로 Claude의 구상을 빠르게 보는 쪽을 선호했다.
- **자세히 정해 준 작업** (인터뷰로 만든 명세)
  - 걸린 시간: low 16분, medium 22분, high 33분, max 79분
  - 명세가 자세하면 단계별 결과가 비슷해진다.

### 저자의 기능 개발 루프

1. 명세를 주고 빠진 걸 인터뷰해 달라고 한다.
2. low로 구현한다.
3. 요지가 맞는지 검토하고, 필요하면 low로 반복한다.
4. high로 검증·테스트한다.

### 어려운 과제 (Terminal-Bench 3.0)

- **effort가 높으면 숨은 엣지케이스를 더 잡는다.** 다만 접근법 자체가 틀린 건 못 고친다.
  - Fable 5.1 low→max (370회 시도): 통과 140→214, 엣지케이스 놓침 59→24, 중앙값 토큰 73k→222k
- **html-js-filter** (HTML 정화기, Fable 5.1): low 1/5 → xhigh 5/5
  - low는 약 2분, 한 번에 작성하고 손으로 쓴 페이지 하나로만 확인했다.
  - high는 약 33분 동안 자기 초안을 공격적으로 리뷰하고, 파서 소스를 읽고, XSS 테스트 모음을 돌리고, 퍼저까지 작성했다.
- **분야별 통과율** (Fable 5.1, low→top)

  | 분야 | low | top |
  |---|---|---|
  | 보안 | 64% | 87% |
  | 하드웨어 | 34% | 75% |
  | ML | 54% | 73% |
  | 과학 | 41% | 61% |
  | 소프트웨어 | 43% | 56% |
  | 미디어 | 18% | 30% |
  | 운영 | 12% | 22% |

  규칙집형 업무는 낮게 유지된다.
- **Opus 5.5 사례**
  - mvcc-lsm-compaction: low 0/5 → xhigh 4/5. 먼저 재현하고, 무작위 테스트를 돌리고, 반쯤 고친 코드에서 테스트가 실패하는지 확인했다.
  - cli-2ph-simplex: 0/5 → high 5/5. 브루트포스 해와 대조하고 큰 문제로 시간을 쟀다.
  - gsea-proteomics: 0/5 → high 4/5. 데이터 전처리를 두 가지로 해 보고 차이의 원인을 파고들었다.

### 저자의 단계별 가이드

| 단계 | 쓰는 경우 | 예 |
|---|---|---|
| low | 빠르게 주고받을 때 | 브레인스토밍, 스케치, 쉬운 수정 |
| medium | 대부분의 일반 개발 | 새 기능 구현 |
| high | 검증이 중요하거나 엣지케이스가 많을 때 | 기존 코드베이스 버그 수정 |
| max | 어려운 문제를 완전히 자율로 | 앱 끝까지 만들고 검증, 중요한 소프트웨어의 보안 취약점 찾기 |

## 주의 (원문 각주)

- 수치는 Anthropic 내부 실행 기준이다: 과제당 5회, Fable 5.1은 제품 안전장치를 끈 상태, 보안 과제는 인터넷 없이 실행.
- 그래서 공개 리더보드와 수치가 맞지 않는다. 화면에 인용할 때는 "원문 내부 실행 기준"이라고 표기한다.
- 그래프·도식은 원문을 그대로 캡처하기보다, 수치만 가져와 우리 스타일로 다시 그리고 출처를 표기한다.
