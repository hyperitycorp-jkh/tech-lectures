# 멀티플레이 웹 FPS 시작 프롬프트 — 클로드 코드에 그대로 붙여 넣기

영상에 나온 FPS 게임을 만들면서 정한 요구사항과 일하는 방식을 프롬프트 한 장으로 정리했다.
실제로는 대화를 주고받으며 14시간 동안 하나씩 정했다. 이 프롬프트는 그 결과를 처음부터 알려 주는 시작점이다. 한 번에 이 게임이 그대로 나온다는 뜻은 아니다.

맥이나 윈도우에서 빈 폴더를 하나 만들고 클로드 코드를 연 뒤, 아래 상자 안 전체를 붙여 넣는다.

```text
너는 웹 게임 개발 PM이야. 브라우저와 폰에서 설치 없이 바로 하는 멀티플레이 FPS(1인칭 총싸움)를 만들어 줘.

[목표]
- 1인 개발이라 사람이 적을 때 서버비가 나오면 안 된다. 게임 서버를 두지 않고 WebRTC P2P로 브라우저끼리 직접 연결한다.
- Three.js + TypeScript + Vite. 첫 화면 JS+CSS는 250KB 이하(빌드 뒤 자동으로 재는 검사를 만든다). 큰 것(서버 SDK·모델)은 첫 화면 뒤에 불러온다.
- 스페셜포스처럼 방 목록 로비 + 방 만들기 + 빠른 시작.
  · 빠른 시작은 대기 0초: 빈자리는 AI가 채우고, 사람이 들어오면 AI 자리를 넘겨받는다.
- 모드: 팀 데스매치(목표 처치 수), 섬멸전(다 쓰러지면 끝), 혼자 하는 연습.

[네트워크]
- 방장 판정형 스타 구조: 방장 브라우저가 시뮬레이션을 돌리고, 참가자는 입력만 보낸다. 상태는 초당 30번 보낸다.
- 참가자 화면은 0.1초쯤 늦게 그려서 부드럽게 보이게 한다(보간).
- Firebase Firestore는 방 목록과 연결 신호(시그널링)만 맡는다. STUN은 무료 공개 서버를 쓰고, 막힌 망에서만 TURN 중계(Cloudflare 등)를 쓴다. TURN 자격 증명은 서버 함수가 발급한다.
- 공정성: 맞았는지는 쏜 순간으로 되감아 판정한다(최대 0.25초). 0.1초 안에 서로 쏘면 둘 다 인정한다. 방장이 나가면 다른 사람이 이어받는다. 방장은 연결이 가장 좋은 사람으로 정한다.

[구조]
- 시뮬레이션은 렌더러·DOM을 모르는 순수 코드로 둔다: Match.step(dt, inputs). 시드 난수만 써서, 같은 입력이면 같은 결과가 나와야 한다.
- 봇도 사람과 같은 모양의 입력을 만든다. 연결이 끊긴 사람은 봇이 대신 조종한다.
- 엔진(화면 전환·입력·3D 무대·네트워크)과 게임 내용(맵·무기·문구)을 나눈다. 다음 게임에서 엔진을 다시 쓸 수 있게.
- 에셋은 무료(CC0) 모델만 쓰고 출처를 CREDITS.md에 적는다. 실제 장소 맵을 만들면 OpenStreetMap 자료(ODbL)를 쓰고 "© OpenStreetMap contributors"를 표기한다.

[폰]
- 가로 화면. 버튼은 7개 이하로 두고, 나머지는 상황에 맞을 때만 띄운다. 노치를 피하고 버튼은 44px 이상.

[작업 방식]
- 큰 일은 에이전트에 나눠 맡긴다(엔진·게임·네트워크·화면). 각자 git worktree에서 동시에 작업하고, 테스트를 통과한 것만 main에 합친다.
- 처음부터 자동 검사를 같이 만든다:
  · 시뮬레이션 단위 테스트
  · AI끼리 붙여서 한 판 템포 재기(너무 늘어지거나 너무 빨리 끝나지 않게)
  · 독립된 브라우저 두 개를 자동으로 띄워 빠른 시작했을 때 같은 판에 들어가는지
  · 화면 글자 잘림·노치·버튼 크기 검사(폰 가로·PC 해상도별 스크린샷)
- 배포할 때 이전 빌드 파일을 남기고 html은 캐시하지 않는다(배포 직후 옛 코드 조각이 404 나지 않게).

[먼저 할 일]
1. 혼자 하는 팀 데스매치 한 판(AI 상대)이 돌아가게 만들고 실행 방법을 알려 줘.
2. 그다음 온라인(P2P) → 로비·빠른 시작 → 폰 화면 순서로 넓혀 줘.

애매한 건 멈추지 말고 합리적인 기본값으로 진행하고, 단계마다 무엇을 골랐는지 알려 줘.
```
